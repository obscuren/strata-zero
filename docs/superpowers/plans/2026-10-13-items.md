# Items Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Items carry perks, grants and uses; the character derives everything from equipment; one `apply` function runs every item action; a generic popup gives the deck Caves-of-Qud-style item menus.

**Architecture:** The `game` crate gains the model (`Perk`, `Use`, `Ability`), derived character values, `Ground` piles and `Action`/`apply`. The app wraps `apply` in `actions::perform`, which also runs effects on the walker and `AppState`. A `Popup` screen pushed over the deck fires `Pick`s; the deck opens pickers and verb menus on Space.

**Tech Stack:** Rust 2024, ratatui, crossterm, serde + ron, thiserror. Tests: `cargo test -p game`, `cargo test -p cyberpunk`.

**Spec:** `docs/superpowers/specs/2026-10-13-items-design.md`

## Global Constraints

- Space is the one interact key; Enter is an alias in the deck.
- Nothing derived is cached on the character; every derived value scans equipment on read.
- Every refusal is an `Err(String)` with a plain reason; messages are the exact strings in the spec.
- Colours and chrome come from the deck: CYAN `Rgb(0,229,255)`, MAGENTA `Rgb(255,0,200)`, DIM `Rgb(120,130,145)`, TEXT `Rgb(205,212,222)`, PANEL_BG `Rgb(4,6,10)`, BAR_BG `Rgb(0,60,70)`, glass factor 0.45, typewriter reveal 10 ticks for popups.
- `cargo fmt --all` and `cargo clippy --workspace --all-targets -- -D warnings` clean at every commit.
- Commit trailer: `Co-Authored-By: Claude Fable 5.1 <noreply@anthropic.com>` and `Claude-Session: https://claude.ai/code/session_01XUU3ja2Kw6dEz92VZnXrMb`.

## Review Focus

1. Equip into a slot whose previous occupant is the only thing granting the ability currently cooling: the `fired` entry must stay harmless (no panic, ability simply gone from the list). Test in Task 2 (`abilities()` after `equipment.clear()`).
2. Dropping or using the last unit of a stack must remove the stack, never leave `qty: 0` (Task 4 tests assert `count == 0` and the inventory length).
3. Heal on a full character must be refused? No: it is applied with `+0 hp` and still consumes one (spec: "raises hp by up to n"). Task 4 pins `+0 hp`? Ruling: a use that heals nothing still consumes, message says `+0 hp`; test it.
4. The popup anchored near the bottom-right of a 100x30 terminal must clamp fully on screen (Task 6 test).
5. Overburdened readout must use the same `weight()` the footer uses, so both agree to one decimal (Task 7 test compares the two strings).
