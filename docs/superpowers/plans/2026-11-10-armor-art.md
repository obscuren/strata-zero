# Armor Art Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The five armor pieces show their drawings in the blueprint window and the GEAR & INVENTORY viewer, through a picture any item can carry.

**Architecture:** `flavor/item_art.ron` (written by the mock's `export.py`) maps item ids to a `Picture`: pixel rows, a colour per char, and text labels. `Content` loads and validates it; the blueprint window gets an `Inspect::Pictured` whose `Art` folds the pixels through a `Pen`, and the KIT viewer takes it through `preview_art`.

**Tech Stack:** Rust, ratatui, serde + RON; Python 3 for the generator.

**Spec:** `docs/superpowers/specs/2026-11-10-armor-art-design.md`

## Global Constraints

- Build into `--target-dir target/smoke`, never `target/`.
- Check both front ends (the five commands in CLAUDE.md) before the last commit.
- A picture is 1 to 88 pixels wide and an even number of rows, 2 to 44.
- Pixel chars are ASCII letters and digits; `.` is empty and takes no colour.
- Labels are non-empty printable ASCII lying wholly on the picture's cells, drawn bold.
- `flavor/item_art.ron` is generated: change `gen.py`/`export.py`, then run
  `python3 -I docs/superpowers/specs/2026-11-10-armor-art-mock/export.py flavor/item_art.ron`.

## Review Focus

- A picture worn in a slot (the rack's tile, `Detail::Slot`) shows in the KIT viewer as one carried does — test in Task 2.
- The tallest picture (44 rows) at 100×30 stays inside the KIT viewer and the blueprint body — test in Task 2.
- `m` and `s` on a pictured item do nothing and the hint says only `esc close` — test in Task 2.
- A label past the picture's right edge or bottom row is rejected — test in Task 1.
- An item carrying both a look and a picture is rejected — test in Task 1.
